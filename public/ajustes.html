Alertas de exámenes

Controla si se muestra una alerta en las historias clínicas cuando existen exámenes solicitados sin resultado subido.

Tu rol puede consultar esta configuración, pero no cambiarla.

Cómo funciona

La alerta aparece al inicio de la historia del paciente y en la consulta cuando hay exámenes con estado “Solicitado” y sin archivo de resultado.

Al subir el resultado, el examen pasa a “Recibido” y deja de contar para la alerta.

Visitas simultáneas

Controla si el sistema permite que un médico tenga varias citas en el mismo horario o si bloquea las visitas simultáneas.

Si está desactivado, el sistema impedirá agendar dos citas para el mismo médico a la misma hora. Si está activado, permitirá varias visitas simultáneas.

La agenda abrirá en esta vista. Los botones Lista, Jornada y Calendario seguirán disponibles para cambiar en cualquier momento.

Tu rol puede consultar esta configuración, pero no cambiarla.

Cómo funciona

La validación se aplica al crear o editar una cita. Si las visitas simultáneas están bloqueadas, una segunda cita en el mismo horario y con el mismo médico será rechazada con un mensaje.

WhatsApp Business API

Configura Meta Cloud API para enviar confirmaciones de citas por WhatsApp.

Copia esta URL en Meta → WhatsApp → Configuración → Webhooks.

Tu rol puede consultar esta configuración, pero no cambiarla.

Cómo configurar

1. Crea una app en Meta for Developers y habilita WhatsApp Business.

2. Copia el Phone Number ID y un token permanente de usuario del sistema.

3. Crea y aprueba una plantilla con 4 parámetros en el cuerpo, en este orden: {{1}} nombre, {{2}} fecha, {{3}} hora y {{4}} médico.

Ejemplo: “Hola {{1}}, le recordamos su cita en ISIM el {{2}} a las {{3}} con {{4}}.”

El teléfono de la paciente se normaliza a formato internacional. Para Ecuador se usa +593.

Migrar base de datos anterior

Sube el respaldo old_db.sql del sistema anterior. Primero se analizarán los datos y luego podrás confirmar la migración.

El sistema corrige tildes y ñ cuando el respaldo mezcla UTF-8 con Latin-1. Los textos que ya vienen ilegibles en el archivo original no se pueden reconstruir: se conservan y pueden corregirse después desde cada consulta.

Tamaño máximo: 150 MB.

Depurar duplicados

Revisa pacientes repetidos por cédula o nombre y consultas idénticas. Se conserva una sola ficha y se mueven sus citas, historias y exámenes.

Tu rol puede consultar esta configuración, pero no ejecutar migraciones.

Orden de la migración

  1. Catálogos de diagnósticos, medicinas, tratamientos e informes.
  2. Pacientes, con cédulas temporales y marca de datos pendientes.
  3. Citas y citas históricas para consultas sin cita.
  4. Consultas clínicas, recetas y exámenes.

Antes de ejecutar se crea un respaldo automático de la base actual. La migración se fusiona con los datos existentes y no elimina registros.

Versión y actualizaciones

La versión instalada se muestra siempre en la cabecera del sistema y en la pantalla de acceso. Esta preferencia controla si las pantallas abiertas se recargan solas cuando detectan una versión nueva.

Compilación—

Si está activo, la pantalla se recarga sola cuando no hay un cuadro de diálogo abierto ni un campo en edición. Si está desactivado, aparece el aviso Actualizar ahora y cada usuario decide cuándo recargar.

Tu rol puede consultar esta configuración, pero no cambiarla.

Cómo publicar una actualización

  1. Sube los cambios a la rama de producción del repositorio.
  2. La plataforma de despliegue reconstruye y reinicia el servicio.
  3. Los navegadores detectan la versión nueva en un máximo de 60 segundos.

Esta preferencia no instala código en el servidor: eso lo hace la plataforma (Render, Railway, Fly.io o tu VPS). Define BUILD_ID con el hash del commit para identificar cada despliegue.
